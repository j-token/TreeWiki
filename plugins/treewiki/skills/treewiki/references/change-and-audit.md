# Change and audit

Before change, read ancestor maps, active applicable contracts, linked decisions, validation evidence, and vocabulary. Search with ACL first, then read candidates directly. Record affected files, contract checks, tests, index implications, and upgrade drift.

After change, preserve stable IDs, update related contracts and verification evidence, assess glossary candidates, and run validation. Reindex only with approval. Audit is read-only and reports duplicate IDs, broken maps/relations, invalid memory provenance or share boundary, stale release/copy/schema state, duplicate hook registration, and unsupported active dependencies.
