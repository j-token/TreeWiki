# LMWiki 도입 절차

## 목표 구조

```text
AGENTS.md
.knowledge/
└── config.yml
docs/
├── contracts/
├── decisions/
├── runbooks/
├── concepts/
├── references/
└── vocabulary/
    └── topics.yml
```

## 구축 순서

1. 기존 지도, Markdown, 코드 진입점, 테스트와 Git 상태를 조사한다.
2. 임베딩 사용 의향과 외부 전송 정책을 결정한다.
3. 없는 디렉터리와 기본 파일만 만든다.
4. 기존 문서를 유형 후보로 분류하고 중복 원본을 찾는다.
5. ID, 상태, 권위, 주제, 적용 범위와 관계를 부여한다.
6. 루트와 지역 `AGENTS.md`에서 코드 영역과 계약을 연결한다.
7. 정적 검증을 통과시키고 선택적으로 첫 청크 manifest를 만든다.
8. 구축 결과와 미해결 문서를 `lmwiki-steward`에 인계한다.

## 분류 기준

| 유형 | 판별 질문 |
| --- | --- |
| `contract` | 시스템이 반드시 지켜야 하는 동작이나 경계인가? |
| `decision` | 무엇을 왜 선택했는가? |
| `runbook` | 운영 상황에서 순서대로 실행할 절차인가? |
| `concept` | 용어와 작동 원리를 설명하는가? |
| `reference` | 외부 사양이나 코드에서 파생된 참조 정보인가? |
| `map` | 다른 코드·문서 진입점을 안내하는가? |

한 문서가 여러 질문에 답하면 원본 의미를 유지한 채 분리 후보로 표시한다. 의미가 불확실하면 `draft`로 두며 자동으로 계약으로 승격하지 않는다.

## 기존 파일 처리

- 기존 파일을 덮어쓰지 않는다.
- 이동 전 모든 상대 링크와 Git 추적 여부를 확인한다.
- 추적 중인 파일은 가능한 경우 `git mv`로 이동한다.
- 같은 사실이 반복되면 즉시 삭제하지 않고 권위 있는 원본 후보를 정한 뒤 중복 문서에서 링크한다.
- 대량 이동은 코드 변경과 같은 커밋에 섞지 않는다.
