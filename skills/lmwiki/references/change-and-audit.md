# 변경과 감사

## 변경 전

1. 작업 경로에서 가장 가까운 `AGENTS.md`와 루트까지의 상위 지도를 읽는다.
2. `applies_to`가 겹치는 활성 계약, 결정, runbook과 검증 진입점을 수집한다.
3. 통제어휘의 표준 키와 이명으로 관련 문서 위치를 찾고, 저장소 고유 명칭은 용어집에서 뜻을 확인한다.
4. `depends_on`, `derived_from`, `verified_by`, `supersedes` 관계를 따라 필수 읽기 집합을 확장한다.
5. 변경할 코드·문서, 적용 계약, 테스트와 예상 색인 변경을 내부 작업 목록으로 만든다.

## 변경 후

- 계약이 적용되는 코드를 바꿨으면 계약과 `verified_by` 근거를 함께 검토한다.
- 새 문서는 `assets/`의 유형별 템플릿을 사용하되 ID, 주제, 범위와 관계를 저장소에 맞게 바꾼다.
- 파일 이동이나 제목 변경으로 문서 ID를 바꾸지 않는다.
- 검증기를 실행하고 오류 0건을 확인한다.
- 임베딩이 활성화됐고 관리 문서가 바뀌었으면 승인된 `manage reindex --apply`로 파생 색인을 갱신한다.

## 감사

감사는 읽기 전용으로 수행한다. 중복 ID, 끊어진 지도 링크, 오래된 검토일, 활성 문서의 폐기 문서 의존, 검증 근거 없는 활성 계약, 출처 없는 기억과 ACL 경계를 보고한다. 날짜 경과만으로 문서를 자동 폐기하지 않는다.
