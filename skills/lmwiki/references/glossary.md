# 용어집 계약

팀원과 AI가 저장소의 대상을 같은 명사로 지칭해야 할 때 `docs/vocabulary/glossary.yml`을 권위 있는 원본으로 사용한다. 문서 분류용 `topics.yml`과 합치지 않는다.

```yaml
terms:
  - term: 워크스페이스
    description: 사용자가 현재 작업 대상으로 연 저장소 루트와 그 안의 파일 집합.
```

- 최상위 `terms`는 배열이다.
- 각 항목의 `term`과 `description`은 공백이 아닌 문자열이며 필수다.
- 앞뒤 공백과 대소문자를 무시했을 때 같은 `term`을 두 번 등록하지 않는다.
- 별칭, 상태, 소유자처럼 아직 계약하지 않은 필드는 필수로 만들지 않는다.
- 용어를 추가하거나 바꾼 뒤 `manage validate`를 실행한다.
- 읽을 때는 `query glossary <repository> [term]`을 사용한다. `term`을 생략하면 전체를, 넣으면 용어와 설명에서 일치하는 항목을 반환한다.

## 지식 변경 게이트

관리 대상 지식을 추가하거나 바꿀 때마다 새 명칭, 약어, 계층, 상태, 역할과 제품 개념을 검토한다. 문서 frontmatter의 `glossary_terms`에 그 문서가 사용하는 저장소 고유 용어를 선언하고 `query glossary-candidates`로 미등록 항목을 확인한다.

- 새 개념이면 용어를 추가한다.
- 기존 개념의 뜻이 바뀌었으면 설명을 갱신한다.
- 일반어이거나 기존 의미가 유지되면 용어집을 바꾸지 않고 완료 보고에 근거를 남긴다.
- CLI는 후보를 보고할 뿐 용어를 자동 등록하지 않는다.
